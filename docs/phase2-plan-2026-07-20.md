## 2. Advisor corrections taken

### 2.1 The second scenario stays single-cell — a sheared storm is Phase 3

The original plan had a deliberately *sheared* second scenario, justified as the
known-asymmetric test asset that Phase 1 carried item #1 demands for the Y-flip. The
advisor killed both halves of that:

- **Phase boundary.** The charter puts "multicell/supercell scenarios" in Phase 3. A
  storm sheared enough to be an *unambiguous* handedness test is organized-regime
  physics pulled forward.
- **The motivation evaporated.** Carried item #1 requires the Y-flip be verified "before
  Phase 2 **placement code** ships" — that is the UE actor `scale.y = -100`. The owner
  deferred UE, so nothing in this phase ships placement code. **Carried item #1 is
  therefore deferred with the UE app, not discharged here.**

The second scenario exists to make "selectable" mean something and to exercise the config
parameterization — which is the actual goal. Single-cell regime, 500 m preview tier.
If it carries mild asymmetry, that is a free sanity-check on the *diorama's* own
E-W/N-S orientation (a bug the axisymmetric Phase 1 cell would mask) — a bonus, not a
reason to build a supercell.

### 2.2 The regression gate is on decoded arrays, not VDB bytes

VDB files are not guaranteed byte-reproducible (embedded metadata, library version
strings, compression ordering), and the manifest changes *by design* this phase. A
byte-diff gate would fail spuriously. The gate is therefore:

- **decoded voxel arrays** (`.densevol` / pre-writer numpy) **identical**, and
- **manifest identical except the fields deliberately changed.**

### 2.3 "Radar view" and "layers" had to be pinned before T5/T6, not assumed

Recorded above in §1. The risk the advisor flagged was assuming the diorama's existing
dBZ layer already *was* the radar view. It is not — an earlier advisor caught and the
design doc records that it is peak dBZ along the **view ray**, explicitly not composite
reflectivity. Both will now exist, and must stay distinctly labelled (T9).

## 4. The scenario system's central design decision

The refactor splits today's single `pipeline/cm1post/config.py` in two, along the line
between *what is frozen by the format contract* and *what varies per scenario*. Getting
this line right is the whole point: putting a frozen quantity in the per-scenario JSON
invites someone to change it per scenario and silently break the SVT import contract.

**`cm1post/contract.py` — frozen, one per `format_version`, NOT per scenario:**
channel names and order, `SOURCE_FIELDS`, activity thresholds, diagnostic-channel set,
the SVT texture map, encodings. Task 3 proved UE 5.8's default grid→SVT assignment
reproduces this map exactly; *changing a channel name forces an SVT import re-test*.
Thresholds live here too because the padded bbox is sized at these values — a per-scenario
override would decouple the sweep from the export and silently clip the storm.

**`cm1post/scenario.py` — per-scenario, loaded from `sim/scenarios/<name>.json`:**
name, kind, description, run dir, export voxel size, crop half-width and z-top, and the
CM1 deck parameters. `NX/NY/NZ/ORIGIN_M` become derived properties rather than module
constants.

**CM1 deck generation is template + overrides, not full generation.** The validated
namelist has ~8 KB of parameters that must not drift. The scenario JSON specifies only
what it changes (`nx`, `dx`, `iwnd`, …); the generator applies those over the validated
base template and records which keys it overrode. This gives a second regression gate:
**the generated `single_cell_500m` deck must reproduce the committed hand-written
`sim/single_cell/namelist.input`** (modulo comments and key ordering).

## 7. Standing method rules inherited

- Any "it renders" claim comes from a real GPU, never `-nullrhi` (Phase 1's most
  load-bearing lesson). In this phase that means the diorama on a real browser GPU, with
  numeric verification rather than eyeball where a number is available.
- A non-foregrounded Chrome tab halts rAF — the canvas captures black and "buffering…"
  sticks. Foreground the tab before any diorama capture.
- Physics through simulation: the second scenario's character must fall out of its CM1
  environment, never be scripted. Diagnostics (`dbz`, `cref`) never feed back.
